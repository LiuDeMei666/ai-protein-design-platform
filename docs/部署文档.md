# AI 辅助蛋白设计平台 · 部署文档

版本 0.1.0 ｜ 适用于企业内网单机部署

---

## 一、环境要求

### 1.1 硬件

| 项目 | 最低 | 推荐 | 说明 |
| --- | --- | --- | --- |
| CPU | 4 核 | 16 核以上 | 序列校验、性质计算为纯 CPU 运算 |
| 内存 | 16 GB | 32 GB 以上 | ESM-2 650M 载入后约占用 3 GB |
| GPU | 可选 | 1× NVIDIA（显存 ≥ 16 GB） | **无 GPU 也可运行**，会自动降级到 CPU 与 35M 小模型 |
| 磁盘 | 20 GB 可用 | 100 GB 以上 | ESM-2 权重约 2.5 GB，结构/嵌入缓存按分析量增长 |

> 已验证环境：2 × Tesla V100 32GB，驱动 535.183.01，CUDA 12.4。

### 1.2 软件

| 组件 | 版本 | 备注 |
| --- | --- | --- |
| 操作系统 | Linux x86_64 | 已在 Ubuntu / glibc 2.35 验证 |
| Python | 3.11 | 本项目在 conda 环境 `dbz` 中运行 |
| CUDA 驱动 | ≥ 525 | 仅在使用 GPU 时需要 |

## 二、安装步骤

### 2.1 创建 conda 环境

```bash
conda create -n dbz python=3.11 -y
conda activate dbz
```

> **重要**：若本机存在用户级 site-packages（`~/.local/lib/pythonX.Y/site-packages`），
> 必须设置 `export PYTHONNOUSERSITE=1`，否则 `pip` 可能被用户级安装劫持，
> 把包装到错误的解释器里（本项目开发过程中实际踩过这个坑）。

### 2.2 安装 Python 依赖

```bash
cd /path/to/danbaizhi
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

`torch==2.5.1` 在 PyPI 上的 Linux wheel 即为 CUDA 12.4 构建，与本机驱动匹配。
若需其它 CUDA 版本，改用官方源：

```bash
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121
```

### 2.3 获取 ESM-2 权重

**必须走镜像**：实测 `huggingface.co` 直连失败（SSL 连接错误），
`hf-mirror.com` 可用。

```bash
python scripts/download_esm2.py                 # 主模型（约 2.5 GB）
python scripts/download_esm2.py --fallback      # 额外下载 CPU 降级小模型（约 150 MB）
python scripts/download_esm2.py --list          # 仅检查本地缓存状态
```

权重落在 **项目内** 的 `models/hf_cache/`，不会污染本机已有的 HuggingFace 缓存。

### 2.4 获取前端第三方库

```bash
python scripts/fetch_vendor_assets.py
```

该脚本按 `jsdelivr → npmmirror → unpkg → bootcdn → cdnjs` 顺序逐个镜像回退，
全部失败时**不会生成残缺文件**，前端会自动切换到无依赖的 Canvas 降级视图（不白屏）。

> **为什么必须 vendor**：本机 Node 版本为 v12.22.9，无法运行 Vite/React 现代构建链，
> 因此前端采用零构建的原生多页应用，第三方库只能以静态文件形式本地引入。
> 企业内网通常无法访问公网 CDN，若依赖 CDN 会直接白屏。

### 2.5 获取标准序列与密码子表

```bash
python scripts/fetch_seed_sequences.py    # UniProt 拉取胶原/工业酶/蛋白A 标准序列
python scripts/fetch_codon_usage.py       # Kazusa 拉取 5 个宿主的密码子使用表
```

两者都**不内置人工编造的序列或频率**：要么真实拉取，要么明确报错。

## 三、启动与自检

### 3.1 启动服务

```bash
bash run_server.sh
```

浏览器打开 `http://<服务器IP>:8848`。

接口文档：`http://<服务器IP>:8848/docs`（Swagger UI，可直接在线试调）。

### 3.2 自检

```bash
curl -s http://127.0.0.1:8848/api/health | python -m json.tool
```

关注以下字段：

| 字段 | 期望 | 异常处理 |
| --- | --- | --- |
| `healthy` | `true` | 为 `false` 时看 `database.ok` 与 `structure.providers` |
| `database.ok` | `true` | 检查 `data/db/` 目录写权限 |
| `torch.cuda_available` | `true` | 为 `false` 时平台仍可用，但速度显著下降 |
| `structure.providers.esmatlas.available` | `true` | 为 `false` 说明外网不通，需部署本地 ESMFold 或接受 stub 占位 |
| `embedding.main_model_cached` | `true` | 为 `false` 请执行 2.3 的下载脚本 |

## 四、离线（内网）部署

企业内网无法访问外网时，按以下流程准备离线包。

### 4.1 在有网机器上准备

```bash
# 1) 创建环境并安装依赖
conda create -n dbz python=3.11 -y
conda activate dbz
pip install -r requirements.txt

# 2) 下载权重与前端资源
python scripts/download_esm2.py --fallback
python scripts/fetch_vendor_assets.py

# 3) 拉取参考数据（密码子表、标准序列）
python scripts/fetch_codon_usage.py
python scripts/fetch_seed_sequences.py

# 4) 打包
tar -czf danbaizhi-offline.tar.gz \
    --exclude='data/cache' --exclude='data/db' --exclude='.playwright-cli' \
    requirements.txt run_server.sh configs backend frontend data/seeds models scripts docs
```

### 4.2 在内网机器上恢复

```bash
tar -xzf danbaizhi-offline.tar.gz -C /opt/danbaizhi
# 复用 conda 环境：把有网机器的环境目录整体拷贝到内网机器的同路径下，或重建后离线安装 wheel
```

### 4.3 离线模式下的行为

| 能力 | 离线可用性 |
| --- | --- |
| 序列校验、生物物理量、性质预测（9 项指标） | ✅ 完全可用（关闭「使用结构增强」与「使用 ESM-2」） |
| 突变设计（零样本打分） | ✅ 可用（ESM-2 权重已在本地） |
| 三维结构预测 | ⚠️ 需本地部署 ESMFold，否则降级为占位结构并**明确标注** |
| 蛋白语言模型 | ✅ 权重本地化后完全离线推理 |

**本地 ESMFold 部署（可选，用于离线结构预测）**：

```bash
pip install fair-esm
# openfold 需按官方仓库单独安装（编译依赖较重）
```

安装后平台会自动从 `esmatlas → local_esmfold → stub` 降级链中选择可用的实现。

## 五、配置说明

配置优先级：**环境变量 / `.env` > `configs/default.yaml` > 代码内默认值**。

### 5.1 环境变量（复制 `.env.example` 为 `.env` 后修改）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DBZ_HOST` / `DBZ_PORT` | `0.0.0.0` / `8848` | 监听地址 |
| `DBZ_STRUCTURE_PROVIDER` | `auto` | `auto` / `esmatlas` / `local_esmfold` / `stub` |
| `DBZ_DEVICE` | `auto` | `auto` / `cuda` / `cpu` |
| `DBZ_USE_FP16` | `true` | GPU 上使用半精度推理 |
| `DBZ_JOB_WORKERS` | `2` | 作业线程池大小 |
| `DBZ_SERIALIZE_HEAVY_JOBS` | `true` | 重计算作业串行化，避免显存争抢 |
| `DBZ_API_KEY` | 空 | 留空则不启用鉴权；设置后所有业务接口需 `X-API-Key` 头 |
| `HF_ENDPOINT` | `https://hf-mirror.com` | 权重下载镜像 |

### 5.2 平台参数（`configs/default.yaml`）

可调项包括：9 项指标的评分权重、组合突变搜索参数、扫描位点上限、
三类规则包的保护规则、宿主表达体系、风险等级阈值、结构统计参数。
**修改后无需改代码**，重启服务或调用 `App.refreshStatus()` 即可生效。

## 七、常见问题

### Q1 `pip install` 报 `SystemExit: 1` 或装到了 python3.10

**原因**：本机存在用户级 pip（`~/.local/bin/pip`），劫持了 conda 环境的 pip。
**解决**：始终使用 `python -m pip`，并设置 `export PYTHONNOUSERSITE=1 PIP_USER=0`。

### Q2 权重下载失败 / SSL 错误

**原因**：`huggingface.co` 直连不可用（实测 curl exit 35）。
**解决**：确认 `HF_ENDPOINT=https://hf-mirror.com`；`curl -I https://hf-mirror.com` 应返回 200。

### Q3 单次结构预测很慢（几十秒到几分钟）

**原因**：ESM Atlas 是**在线服务**，耗时随序列长度近似二次增长。
实测：72 aa 约 2.3 秒；382 aa 约 183 秒。
**解决**：
- 350 残基以上的序列建议先用「域切分」或指定区段分析；
- 长序列结果会自动落盘缓存，**重复分析零成本**；
- 大批量分析请在工作台观察作业队列，不要重复提交。

### Q4 结构预测返回 `stub` 占位结构

**原因**：在线通道不可达且未部署本地 ESMFold，平台降级到占位 Provider。
**关键提示**：占位结构的 pLDDT 被刻意压低到 30-45，并且**不会参与性质评分**
（平台会自动剔除，避免用假结构惩罚真序列）。所有相关结果都会带明确标注。

### Q5 超长序列（如全长胶原蛋白）预测结果怎么解读

平台会自动分片折叠（每片 ≤ 400 残基），并把片段边界写进结果。
**片段之间的相对空间取向未经建模**，因此跨片段的整体构象不可信；
但**片段内部的二级结构与置信度评估仍然有效**。
平台**绝不会静默截断**，所有分片信息都会在结果与界面中标注。

### Q6 前端图表或 3D 视图空白

**原因**：`frontend/vendor/` 下缺少第三方库（离线部署时未拷贝）。
**解决**：执行 `python scripts/fetch_vendor_assets.py`，或从有网机器拷贝整个
`frontend/vendor/` 目录。缺少 3Dmol 时平台会自动降级为 Canvas 残基轨道图，
**不会白屏**（置信度分布与热点位置完整保留）。

### Q7 实验数据导入后「训练」按钮报样本不足

**原因**：训练需要**去重后的样本数**（按 `序列 + 突变` 计），而不是记录条数。
**解决**：至少积累 8 个不同突变体的实测数据；建议 15 个以上再训练，
否则评估指标不具备参考价值（平台会在返回中明确提示）。

### Q8 如何备份 / 迁移

需要备份的内容只有三处：

```bash
data/db/platform.db       # 全部业务数据
models/property_heads/    # 训练好的模型版本
data/validation/          # 验证案例结果（可选）
```

ESM-2 权重与磁盘缓存可随时重新生成，无需备份。
